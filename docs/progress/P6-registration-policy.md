# P6. Политика регистрации

Ветка: `feat/registration-policy`
Статус: закрыта, влита в `main`.

---

## Решение владельца (2026-08-28)

Прод-модель: у нового пользователя N бесплатных генераций, дальше — покупка.
Учёт потребления уже есть (P4). Пока бот используется только для тестов —
регистрация остаётся открытой. Ограничение числа пользователей в проде
закроет биллинг, а не вайтлист.

## Что сделано

- `TELEGRAM_ALLOWED_USER_IDS` (csv Telegram-id) — выключенный по умолчанию
  переключатель закрытой беты в `POST /api/v1/auth/telegram`
  (`_parse_telegram_allowlist`, `api/v1/auth/router.py`):
  - не задан или пуст → регистрация открыта (текущее поведение);
  - задан → id не из списка получает `403`, проверяется и для существующих
    `tg_*`-аккаунтов (решение владельца: «блокировать тоже»);
  - пустая строка = открыто, потому что compose подставляет `${VAR:-}` как
    пустую строку, когда переменная не задана — в реальном деплое они
    неразличимы (вскрыто упавшим тестом). Полный выключатель входа —
    незаданный `TELEGRAM_BOT_TOKEN` (503).
- Переменная добавлена во все 4 сервиса `docker-compose.yml`, задокументирована
  в `README.md`; контракт для бот-разработчика дополнен кодом `403`
  (`docs/tg/01-auth-telegram.md`).
- 4 интеграционных теста: не задан = открыто; вайтлист пускает своего и режет
  чужого; существующий аккаунт вне списка блокируется; пустая строка = открыто.

## Явно НЕ делаем

- Код приглашения, инвайты — не окупаются на этапе закрытого тестирования.
- Биллинг «N бесплатных + покупка» — новая задача в `tasks.md` (блок 3),
  решение владельца зафиксировано там.
- Отдельная колонка `telegram_id`, самоудаление аккаунтов.
