Бриф: Telegram Mini App + бот для Presenton
Главное, тезисно
1. Существующий фронт в Mini App не переносим. Нужен отдельный лёгкий интерфейс.

Причины конкретные, не вкусовые:

Слайд — это canvas шириной 1280px. В редакторе стоят проверки matchMedia("(min-width: 1280px)"), от которых зависит вся раскладка. На экране 390px редактировать нечего.
63 рантайм-зависимости, среди них @babel/standalone (~2.5 МБ), konva, mermaid, recharts. Mini App грузится по мобильной сети при каждом открытии.
Редактирование в v1 не нужно вообще (решение принято). Значит вся эта тяжесть — за то, что не используется.
Что делаем вместо: экран «форма → генерация → превью → файл». Это отдельный route в том же Next.js-приложении, ничего из редактора не импортирующий. Ориентировочно 300–500 строк.

Полный редактор доступен кнопкой «открыть в браузере» (Telegram.WebApp.openLink) на тот же домен — та же сессия, ничего переписывать не надо.

2. Авторизация — через initData, отдельного логина нет.

Mini App отправляет window.Telegram.WebApp.initData на POST /api/v1/auth/telegram. Мы проверяем подпись, сами создаём аккаунт при первом входе и возвращаем сессионную куку. Дальше все запросы идут с этой кукой, как у обычного веб-пользователя. Ни логина, ни пароля, ни регистрации.

3. Бот не использует общий API-ключ.

Один ключ на всех сложил бы презентации всех пользователей в аккаунт администратора — изоляция данных пропала бы. Бот работает от имени пользователя, его сессией.

4. HTTPS-домен — на твоей стороне, и он блокирует часть работы.

Telegram Mini App требует HTTPS. Плюс от него зависит настройка cookie: в веб-клиенте Telegram Mini App живёт в кросс-сайтовом iframe, куда браузер не отдаёт SameSite=Lax. Нужен SameSite=None; Secure, а Secure без HTTPS не работает. Пока домена нет — авторизацию в веб-клиенте Telegram не проверить.

Что мы предоставим
POST /api/v1/auth/telegram — реализовано
Copy
Запрос:  { "init_data": "<строка window.Telegram.WebApp.initData целиком>" }
Ответ:   200 + Set-Cookie: presenton_session=...
         Тело: { "configured": true, "authenticated": true,
                 "created": true|false,          # true — аккаунт только что создан, можно поприветствовать
                 "id", "username": "tg_<telegram_id>", "role": "user", "created_at" }
         401 если подпись невалидна или initData просрочена (старше 15 минут)
         429 при превышении лимита запросов (10 в минуту с IP, как у /login)
         503 если на сервере не задан TELEGRAM_BOT_TOKEN — это ошибка конфигурации, пиши нам
Передавай initData как есть, не разбирай и не пересобирай — подпись считается по исходной строке, любая пересборка её ломает.

Кука httpOnly, поэтому из JS не читается — это нормально. Все дальнейшие запросы делай с credentials: "include".

Дальше пользователь неотличим от обычного: свои презентации, свои файлы, изоляция на уровне БД.

GET /api/v1/quota — готов
Остаток квоты на генерацию. Один и тот же для Mini App и бота: ходишь с сессией пользователя (credentials: "include"), получаешь JSON {limit, used, remaining, period_hours, resets_in_seconds}; remaining: null — безлимит; 401 — сессии нет/истекла, перелогинься через POST /api/v1/auth/telegram. Рекомендуемый UX и конфигурация — в 03-quota.md.

Превью слайдов картинками — новый, делаем мы
Бэкенд умеет рендерить слайды в PNG на своей стороне. HTTP-обёртки пока нет, сделаем. Это то, что позволяет Mini App не тянуть тяжёлый рантайм: показываешь картинки, а не рендеришь слайды в браузере.

Скажи, в каком виде удобнее — список URL картинок или что-то другое, и нужны ли размеры. Сделаем под тебя, пока не реализовано.

Что уже работает, можно использовать сразу
Генерация
Copy
POST /api/v1/ppt/presentation/generate/async
Тело (обязателен только content):

json
Copy
{
  "content": "тема или подробный промпт",
  "n_slides": 8,
  "language": "Russian",
  "template": "general",
  "export_as": "pptx",
  "tone": "default",
  "verbosity": "standard",
  "web_search": false,
  "include_title_slide": true,
  "include_table_of_contents": false
}
template — одно из: general, modern, standard, swift, dynamic, editorial, executive, momentum.
export_as — только pptx или pdf.
n_slides можно не передавать, модель определит сама. Если include_table_of_contents: true, то n_slides минимум 3.
Вебхуки отправляются всегда, если пользователь подписан — отдельного флага в запросе нет.
Ответ — AsyncTaskModel, из него нужен id задачи и data.presentation_id.

Статус
Copy
GET /api/v1/async-tasks/{task_id}
По завершении в data появляются path (файл) и edit_path (ссылка на редактор).

Есть также GET /api/v1/ppt/presentation/status/{presentation_id}.

Вебхуки
Copy
POST   /api/v1/webhook/subscribe     { "url": "...", "secret": "...", "event": "presentation.generation.completed" }
DELETE /api/v1/webhook/unsubscribe   { "id": "..." }
События: presentation.generation.completed, presentation.generation.failed.

Мы придём POST'ом с JSON и заголовком Authorization: Bearer <secret>.

Важно: подписка привязана к пользователю, который её создал. Одной глобальной подписки «на всё» не получится — либо подписывай каждого пользователя, либо полагайся на поллинг.

Доставку починили: до 4 попыток с задержкой 2/5/10 с, таймаут 10 с на запрос; ретраятся сетевые сбои, 5xx и 429. Поллинг статуса всё равно оставь как страховку — после исчерпания ретраев вебхук может не дойти, и мы об этом узнаем только из наших логов.

Файл
path из завершённой задачи ведёт на /app_data/exports/users/<user_id>/…, доступ по той же куке.

В Mini App нормального «скачать файл» нет — и не надо. Правильный канал у тебя уже есть: бот скачивает файл сессией пользователя и отправляет документом в чат. Это лучше браузерного download, а не костыль вместо него.

Как связать бота и Mini App
Обе поверхности ходят в API от имени одного и того же пользователя (tg_<telegram_id>), так что бот видит презентации, созданные в Mini App, и наоборот. Отдельной синхронизации не нужно.

Боту сессия достаётся так же — через POST /api/v1/auth/telegram. В боте нет initData от Mini App, но есть свой источник подписанных данных (Login Widget / данные апдейта). Скажи, какой путь тебе удобнее, чтобы мы поддержали именно его в эндпоинте — это влияет на нашу реализацию, лучше решить до того, как напишем.

Что нужно от тебя
HTTPS-домен. Блокирует проверку авторизации в веб-клиенте Telegram.
Формат превью слайдов — под тебя делаем, пока не реализовано.
Как бот получает сессию (см. выше) — влияет на наш эндпоинт.

Закрытые вопросы (для истории): что показывать по квоте — остаток до запуска, блок кнопки при remaining: 0, отсчёт из Retry-After / resets_in_seconds при 429 (см. 03-quota.md).
Порядок, который я предлагаю
Сначала мы делаем POST /api/v1/auth/telegram и endpoint превью, ты параллельно поднимаешь домен и собираешь экран на моках. Дальше стыкуемся: авторизация → генерация → превью → отдача файла ботом. Квоты уже работают (03-quota.md) — подключай после основного потока, они не блокируют.
