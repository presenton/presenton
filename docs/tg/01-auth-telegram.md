# 01. Авторизация через Telegram — реализовано

Записка к разделу «Авторизация» из `fyi.md`. Эндпоинт работает, можно стыковаться.

## POST /api/v1/auth/telegram

Запрос:

```json
{ "init_data": "<строка window.Telegram.WebApp.initData целиком>" }
```

Ответ `200` + `Set-Cookie: presenton_session=...` (httpOnly, 30 дней):

```json
{
  "configured": true,
  "authenticated": true,
  "created": true,
  "id": "uuid",
  "username": "tg_<telegram_id>",
  "role": "user",
  "created_at": "..."
}
```

- `created: true` — аккаунт создан этим запросом, можно поприветствовать нового
  пользователя; `false` — вход в существующий.
- `401` — подпись невалидна или `initData` просрочена (принимаем `auth_date`
  не старше 15 минут; свежую `initData` бери при каждом открытии Mini App).
- `403` — на сервере включён вайтлист `TELEGRAM_ALLOWED_USER_IDS`, и id этого
  Telegram-аккаунта в список не входит. Проверяется и для уже существующих
  аккаунтов: попадание в список = возможность входа.
- `429` — больше 10 запросов в минуту с одного IP (лимит nginx, как у логина).
- `503` — на сервере не задан `TELEGRAM_BOT_TOKEN`; это ошибка конфигурации,
  пиши нам.

Сейчас вайтлист выключен (переменная не задана) — регистрация открыта всем,
квота 10 генераций / 24ч на пользователя (`docs/tg/03-quota.md`). Перед
публичным запуском список включат; если увидишь `403` — это значит, что id
пользователя не внесли в `TELEGRAM_ALLOWED_USER_IDS`.

Передавай `initData` как есть, не разбирай и не пересобирай — подпись считается
по исходной строке, любая пересборка её ломает.

Кука httpOnly, из JS не читается — это нормально. Все дальнейшие запросы с
`credentials: "include"`. Дальше пользователь неотличим от обычного веб-
пользователя: свои презентации, свои файлы, изоляция на уровне БД.

## Ограничение: веб-клиент Telegram

В мобильных клиентах Mini App — top-level WebView, кука `SameSite=Lax`
работает. На `web.telegram.org` Mini App живёт в кросс-сайтовом iframe, куда
браузер Lax-куку не отдаёт — там авторизация пока не сработает. Починка
(`SameSite=None; Secure`) запланирована, но требует HTTPS-домен с твоей
стороны.

## Открытый вопрос: сессия для самого бота

У бота (серверного процесса) нет `initData` от Mini App. Варианты: Login
Widget или подписанные данные апдейта. Скажи, какой путь удобнее — поддержим
именно его в этом же эндпоинте.
